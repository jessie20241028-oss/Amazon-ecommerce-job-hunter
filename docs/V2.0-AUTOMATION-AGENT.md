# v2.0 — Automated Job-Hunting Agent

## Goal

Run a controlled daily pipeline that discovers changes, identifies duplicates, scores evidence-backed opportunities, updates the tracking system and sends a digest. Human approval remains mandatory for external communications and applications.

## Architecture

- Scheduler: triggers a daily run in Asia/Shanghai.
- Source adapters: BOSS直聘, 猎聘, company career pages and user-provided links, subject to permitted access.
- Normalizer: maps source data into the v1.1 common job schema.
- Deduplication service: exact IDs/URLs first, then fuzzy company/title/location/responsibility matching.
- Screening engine: applies hard gates before weighted scoring.
- Storage: Feishu Bitable when authorized; otherwise CSV/JSON export.
- Notification: Feishu message or another user-approved channel.
- Audit log: run ID, timestamps, source status, changes, scoring explanation and action outcomes.

## Daily workflow

1. Start scheduled run; create a unique run_id.
2. Check each source adapter's availability and permitted access.
3. Search configured role/location keywords.
4. Normalize records; malformed records go to a review queue.
5. Deduplicate against stored canonical jobs.
6. Compare previous snapshot and record field-level changes.
7. Apply hard gates: Shenzhen and role match; fixed base >= RMB 12,000/month passes if verified; below threshold fails; unknown/package-only salary remains pending.
8. Score eligible or pending records; score cannot override a failed hard gate.
9. Upsert to Feishu or generate a reviewable export.
10. Generate digest and notify through approved channel.
11. Log success, partial failure or source outage.

## Duplicate detection

Deterministic keys:
- platform + platform_job_id, when available;
- normalized canonical URL;
- internal stable job_uid.

Similarity features:
- normalized company name;
- normalized job title;
- city/district;
- responsibility and requirement text similarity;
- salary range and experience requirements as supporting evidence.

Exact matches may merge automatically while retaining all source links. Strong probable matches go to a duplicate-review queue. Ambiguous records remain separate. Do not merge subsidiaries, staffing agencies and hiring entities without evidence.

## Scoring and ranking

Reuse references/scoring-rules.md. Every score includes dimension-level score, evidence/source URL, confidence and unresolved questions.

Examples:
- 88 points + fixed base unknown = pending, not a qualified A-grade recommendation.
- 72 points + verified base 10K = excluded by salary gate.

## Notification policy

Daily digest:
1. New qualified jobs.
2. New pending-salary jobs worth asking HR.
3. Material changes to existing jobs.
4. Follow-ups due today.
5. Source failures or stale records.

Alert immediately only for configured high-priority events. Avoid one notification per duplicate listing.

## Approval gates

| Action | Automation policy |
|---|---|
| Search public/authorized sources | May run on schedule |
| Normalize, deduplicate, score | May run automatically |
| Write to user's Feishu Base | Only after API connection and write scope are authorized |
| Send notification digest | Only to user-approved destination |
| Draft HR message | May draft automatically |
| Send HR message | Requires explicit approval for the specific message/recipient |
| Share resume or personal data | Requires explicit approval for the specific job and file |
| Submit application | Requires explicit approval for the specific job and final submission |
| Handle CAPTCHA/login/OTP | Stop and ask user; never bypass |

## Reliability requirements

- Idempotency: repeated source item does not create duplicate records.
- Retry: transient errors retry with bounded backoff; persistent failures go to error log.
- Partial failure: successful sources remain usable; failed sources are clearly listed.
- Staleness: source failure is never interpreted as zero vacancies.
- Change detection: preserve old and new values for salary, status, location and responsibilities.
- Observability: each run logs start/end time, source counts, inserted/updated/unchanged/failed counts.
- Kill switch: user can pause schedule and disable a source adapter.
- Data minimization: store only fields needed for job evaluation and application tracking.

## Example configuration

    timezone: Asia/Shanghai
    schedule:
      frequency: daily
      time: "08:30"
    search:
      city: Shenzhen
      keywords:
        - Amazon高级运营
        - 亚马逊精品运营
        - 亚马逊运营组长
        - 亚马逊运营主管
        - Amazon服装运营
    salary_gate:
      currency: CNY
      fixed_base_min_monthly: 12000
      unknown_base: pending
    notifications:
      daily_digest: true
      immediate_high_priority: false
    actions:
      auto_message_hr: false
      auto_submit_application: false
      auto_share_resume: false

This is an example only. Do not enable a schedule or connect a live Base until the user confirms timezone, delivery channel and integration permissions.

## Release acceptance tests

1. Same posting on two sources results in one canonical job with two source links.
2. Unknown fixed base never passes the salary gate.
3. Total compensation cannot populate fixed-base fields.
4. Salary below RMB 12,000 is excluded even if weighted score is high.
5. Failed source is reported unavailable, not as no vacancies.
6. Re-running identical input is idempotent.
7. Changed salary creates a change event and reviewable alert.
8. No HR message or application is sent without job-specific approval.
9. User can pause monitoring and export their data.
