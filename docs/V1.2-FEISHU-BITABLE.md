# v1.2 — Feishu Bitable 求职管理系统

## Objective

Use Feishu Bitable as the operational source of truth for jobs, companies, contacts, communications, applications, interviews and follow-up tasks. Start with CSV import/export before enabling API sync.

## Data model

### 1. 岗位库（Jobs）

| Field | Type | Purpose |
|---|---|---|
| 岗位ID | Text / unique | Internal ID |
| 岗位名称 | Text | Normalized title |
| 公司 | Link to 公司库 | Canonical company |
| 来源平台 | Single select | BOSS直聘 / 猎聘 / 官网 / 用户提供 / 其他 |
| 原始链接 | URL | Source of truth |
| 城市 / 区域 | Select / Text | Shenzhen / district |
| 固定底薪下限(K) / 上限(K) | Number | Fixed base only |
| 综合薪资原文 | Text | Preserve listing wording |
| 综合薪资下限(K) / 上限(K) | Number | Total package, separate from base |
| 薪资核验状态 | Single select | 已核实 / 待HR确认 / 未披露 |
| 硬性条件 | Single select | 通过 / 不通过 / 待确认 |
| 匹配评分 | Number | 0–100 |
| 置信度 | Single select | 高 / 中 / 低 |
| 招聘状态 | Single select | 招聘中 / 状态不明 / 已关闭 |
| 核验状态 | Single select | 已核实 / 部分核实 / 待核实 |
| 首次发现 / 最近核验 | DateTime | First seen / last checked |
| 下一步 / 跟进日期 | Text / Date | Action and due date |
| 备注/证据 | Long text | Evidence and unknowns |

### 2. 公司库（Companies）

公司名称、官网、主营业务、Amazon业务模式、产品类目、供应链/品牌信息、团队规模（如有证据）、工作制度、福利、风险备注、信息来源、最近核验日期。

### 3. HR联系人（HR Contacts）

姓名、职位、所属公司（关联公司库）、联系方式/平台主页、来源、首次联系日期、联系授权备注、隐私备注。只保存求职所需且用户有权保存的信息。

### 4. 沟通记录（Communications）

关联岗位、关联HR、日期、渠道、沟通方向（发出/收到）、消息内容或摘要、发送状态（草稿/待确认/已发送/发送失败）、HR回复、下一步、证据链接。

### 5. 投递记录（Applications）

关联岗位、简历版本、定制文件链接、用户授权状态、授权时间、投递渠道、投递时间、平台回执/截图链接、投递状态（待授权/待投递/已提交/结果待确认/失败/撤回）、备注。

### 6. 面试记录（Interviews）

关联岗位、轮次、面试时间、面试官（可选）、面试形式、准备事项、问题记录、用户复盘、结果、后续动作。

### 7. 待办与提醒（Tasks）

任务名称、关联岗位/HR/投递、截止日期、优先级、状态、提醒方式、完成时间。

## Recommended views

- 今日待跟进：跟进日期 = 今天且状态未完成。
- 高优先级岗位：硬性条件 = 通过，评分 ≥ 80，招聘状态 = 招聘中。
- 薪资待确认：薪资核验状态 = 待HR确认或未披露。
- 待沟通：岗位状态 = 待沟通。
- 投递中：投递状态 = 待授权/待投递/已提交/结果待确认。
- 面试日历：按面试时间排序。
- 已关闭/不匹配：归档视图，避免重复筛选。

After import, convert relationship ID columns into Feishu linked-record fields. Confirm field types, select options and views in the Base UI.

## Sync rules

1. Jobs are upserted by 岗位ID; source URLs and source platform IDs remain attached.
2. Never overwrite a user-edited field with an unreviewed scrape result. Use source snapshot fields or a change-review queue.
3. Keep a timestamped change log for salary, status, responsibilities and location.
4. Do not delete closed jobs; mark closed and archive.
5. API writes require an authorized Feishu app and minimum necessary scopes.
6. Store secrets outside GitHub and never include real candidate contact data in repository fixtures.
7. Test with a sandbox Base before writing to the user's live Base.

## Operating SOP

Daily: review new jobs and evidence; confirm salary-pending jobs with HR; review today's follow-ups; update communications and application statuses; review upcoming interviews.

Weekly: count new, qualified and excluded jobs; review response rate and interview conversion; identify salary mismatch and company-fit patterns; adjust search keywords and scoring only with explicit rationale.

## Privacy and permissions

The Base may contain personal contact details, resume links and interview notes. Set workspace permissions to the smallest practical audience. Do not publish the Base publicly. Do not place secrets or personal data in this public GitHub repository.
