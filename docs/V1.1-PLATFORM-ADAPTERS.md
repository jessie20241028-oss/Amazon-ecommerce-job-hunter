# v1.1 — BOSS直聘 / 猎聘平台适配规范

## Purpose

Add platform-specific discovery instructions while keeping one normalized job record. Platform adapters are data-source adapters, not permission bypasses.

## BOSS直聘 adapter checklist

1. Search Shenzhen + role keyword combinations: Amazon高级运营、亚马逊精品运营、亚马逊运营组长、亚马逊运营主管、Amazon服装运营、欧美站运营。
2. Capture visible title, company, location, salary text, experience, education, work schedule, benefits, responsibilities and source URL.
3. Recruiter online status or platform activity is weak evidence only; it does not prove a vacancy is active.
4. If details require login or are inaccessible, store the listing URL and mark inaccessible/pending; ask the user to inspect or provide a screenshot/link if needed.
5. Confirm fixed base salary with HR when the listing only shows a broad range or total package.

## 猎聘 adapter checklist

1. Reuse the same keyword set and common schema.
2. Capture displayed role and company details plus source URL and capture time.
3. Preserve annual salary wording and convert only when pay period and number of months are explicit. Keep raw wording.
4. Record recruiter/consultant claims separately from the employer's official listing.
5. Verify whether the hiring entity and actual employer are the same when relevant.

## Salary parsing rules

- “综合 15K–25K” is not fixed base.
- “底薪 12K + 绩效” may pass provisionally; mark base as requiring HR confirmation unless source is explicit and reliable.
- “12–20K·13薪” does not prove 12K fixed base; retain raw text and ask what is fixed.
- Annual salary may be converted to monthly equivalent only if amount and payment structure are clear. Do not label it fixed base without evidence.
- Negotiable / 面议 / 底薪不明 => hard_gate_status=pending.
- Fixed base below RMB 12,000/month => hard_gate_status=fail.

## Verification workflow

1. Open original source, not just a search-engine snippet.
2. Record checked date and exact URL.
3. Check whether posting is accessible and whether date/status is visible.
4. Compare duplicate listings and identify meaningful differences.
5. Mark every unknown explicitly.
6. Ask HR targeted questions before upgrading salary or vacancy status to verified.

## Deduplication

- Exact match: same platform + platform job ID, or same canonical URL.
- Probable match: normalized company + normalized title + city/district + responsibility similarity.
- Do not merge solely because titles are similar. Keep all source URLs under one canonical job record.
- If company names differ due to subsidiary/recruiting entity, flag for review rather than silently merging.

## Output expectations

For each search batch, report source and search date; unique jobs and cross-platform duplicates; current/uncertain/closed counts; fixed-base pass/fail/pending counts; top matches and evidence links; inaccessible records requiring manual review.

## Compliance boundary

Use only permitted, accessible pages and platform-approved workflows. Do not evade CAPTCHA, login controls, rate limits, robots restrictions or anti-automation systems. Do not automate messaging or application submission in this adapter.
